# 实时补帧后续代办

更新时间：2026-07-15

## 当前基线

- 使用 RIFE 4.25 完整版 FP16 ONNX，DirectML/D3D12 Buffer 零拷贝推理。
- 固定 2x；仅在目标帧率不超过显示器刷新率时启用。
- 补帧推理分辨率上限可选 1080p、1440p 或 2160p；低于所选上限时保持片源尺寸，默认仍为 1080p。
- 原始视频帧优先；生成帧未按时完成时丢弃，不阻塞播放时钟。
- 字幕在补帧之后按呈现时间轴独立合成，不进入模型输入。
- 当前实播日志达到 `interpolation_effective_multiplier=2.00` 且 `inference_failures=0`。

## 待办

- [x] P0：稳定 HDR/Dolby Vision 补帧亮度。
  - A/B 端点分别应用自己的 HDR10+、DV RPU/CMv4、用户曲线与源峰值，再映射到同一个固定目标显示域。
  - 已实现：HDR10、HLG、原生 DV 和解码器 DV 的 HDR 输入统一进入 display-mapped BT.2020/PQ 张量域；SDR 保持原模型域；左端点只负责播放节拍，不再充当色彩权威。
  - HDR10+ 不再绕过补帧：ST 2094-40 在两端独立内化；补帧开启时关闭 NVAPI HDR10+ Gaming 动态直通，并使用稳定的目标显示元数据，避免生成帧继承左帧的外部显示状态。
  - DV 的 A/B 由 libplacebo 或原生 D3D12 分别完成 RPU/trim 映射；B 的显示域缓存可直接复用为下一组 A，不再要求两帧元数据指纹相同。
  - 最终生成帧合成只接受 SDR 编码域或 display-mapped BT.2020/PQ；源光域 HDR 分支已封死，禁止二次 Tone Mapping。窗口、全屏、显示器峰值或 HDR 配置变化时作废旧补帧。
  - 验收：窗口和全屏切换后均无周期性亮度闪烁，HDR/DV 直通和软件回退不退化。
- [x] P1：加入场景切换保护。
  - 检出硬切镜头时跳过跨镜头生成帧，直接呈现下一个原始帧。
  - Seek、续播、网络再缓冲、解码时间线变化时清空端点帧和在途推理。
  - 已实现：Dolby Vision `scene_refresh_flag` 作为高置信度边界直接跳过；普通 SDR/HDR 在张量预处理 dispatch 中按 16x16 网格异步统计 BT.2020 亮度差，结合变化占比和全局亮度偏移识别硬切；探针结果绑定生成帧槽，异常或未按时完成时仅丢弃生成帧；时间线变化继续通过 epoch 作废旧端点和在途结果。
  - 验收：快速剪辑处无融合鬼影，恢复播放后不引用旧时间线帧。
- [x] P1：确保字幕与 OSD 完全独立于补帧。
  - ASS 位图、动画特效和 OSD 只进入最终合成通道；插值邮箱和生成帧槽不携带字幕/OSD 数据。
  - 验收：小窗、全屏及补帧开关切换时字幕不闪烁、不重建抖动。
- [ ] P2：对 RIFE 4.25 完整版与 Lite 做固定片源 A/B 验证。
  - 对比运动边缘、遮挡区域、动漫线条、快速平移和场景切换伪影。
  - 同时记录生成帧迟到数、有效倍率和推理失败数，确认完整版的画质收益。
- [ ] P2：补齐 Debug 回归日志断言。
  - 检查模型文件名、FP16 输入输出、可配置推理分辨率上限、固定 2x、字幕后合成和时间线重置。

## 推理后端决定

继续以 DirectML FP16 作为主后端。当前效率已满足实时固定 2x，TensorRT-RTX
不会在使用同一模型和精度时带来可感知的画质提升。只有出现持续推理迟到、生成帧
大量丢弃或更高负载目标时，再评估 TensorRT-RTX；AMD/Intel 兼容性仍由 DirectML
承担。
