# 实时补帧后续代办

更新时间：2026-07-15

## 当前基线

- 使用 RIFE 4.25 完整版 FP16 ONNX，DirectML/D3D12 Buffer 零拷贝推理。
- 固定 2x；仅在目标帧率不超过显示器刷新率时启用。
- 片源高于 1080p 时以 1920x1088 对齐尺寸推理，低于 1080p 时保持原始分辨率。
- 原始视频帧优先；生成帧未按时完成时丢弃，不阻塞播放时钟。
- 字幕在补帧之后按呈现时间轴独立合成，不进入模型输入。
- 当前实播日志达到 `interpolation_effective_multiplier=2.00` 且 `inference_failures=0`。

## 待办

- [ ] P0：稳定 HDR/Dolby Vision 补帧亮度。
  - 同一对端点帧必须使用一致且冻结的色调映射、曝光和动态元数据状态。
  - 生成帧不得单独触发曝光统计或元数据切换。
  - 验收：窗口和全屏切换后均无周期性亮度闪烁，HDR/DV 直通和软件回退不退化。
- [ ] P1：加入场景切换保护。
  - 检出硬切镜头时跳过跨镜头生成帧，直接呈现下一个原始帧。
  - Seek、续播、网络再缓冲、解码时间线变化时清空端点帧和在途推理。
  - 验收：快速剪辑处无融合鬼影，恢复播放后不引用旧时间线帧。
- [ ] P1：继续验证字幕完全独立于补帧。
  - ASS 位图、动画特效和 OSD 只进入最终合成通道。
  - 验收：小窗、全屏及补帧开关切换时字幕不闪烁、不重建抖动。
- [ ] P2：对 RIFE 4.25 完整版与 Lite 做固定片源 A/B 验证。
  - 对比运动边缘、遮挡区域、动漫线条、快速平移和场景切换伪影。
  - 同时记录生成帧迟到数、有效倍率和推理失败数，确认完整版的画质收益。
- [ ] P2：补齐 Debug 回归日志断言。
  - 检查模型文件名、FP16 输入输出、1920x1088 上限、固定 2x、字幕后合成和时间线重置。

## 推理后端决定

继续以 DirectML FP16 作为主后端。当前效率已满足实时固定 2x，TensorRT-RTX
不会在使用同一模型和精度时带来可感知的画质提升。只有出现持续推理迟到、生成帧
大量丢弃或更高负载目标时，再评估 TensorRT-RTX；AMD/Intel 兼容性仍由 DirectML
承担。
